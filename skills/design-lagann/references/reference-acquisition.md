# Reference acquisition

Acquire references yourself whenever host capabilities allow it. Asking the user for references is a fallback for inaccessible private material, unclear rights, or an exact source only the user controls.

## Choose a route

- `search`: real brands, current category conventions, factual products, explicit sites, licensed photography, or close-reference work.
- `generate`: original visual-direction exploration when a raster image generator is available and no factual source is implied.
- `hybrid`: search for category truth, then generate one original direction frame. This is the default for a showcase creation with image generation.
- `browser-compose`: the fallback when generation is unavailable. Use searched principles and build the direction in actual HTML/CSS.

## Build a small reference set

Use 3–6 sources total. Give every source exactly one primary role:

1. category pattern;
2. composition;
3. typography;
4. interaction;
5. content tone;
6. asset treatment.

For each source, record its URL or generation provenance, why it qualifies, one reusable relationship, and one thing that must not be copied. Reject mood-board accumulation without a decision role.

## Rights and fidelity

Use public references as analytical evidence, not a component library. Do not copy logos, brand copy, distinctive illustrations, custom icon sets, or a source's full section geometry. Exact reproduction requires a user-owned or licensed reference and explicit authorization. Generated direction frames are proposals and can never substitute for factual content, production assets, or fresh browser acceptance evidence.

## Host execution

When the runtime returns `design-lagann-reference-acquisition-plan`, execute its actions with the host's available web search, image search, image generation, and browser tools. If one executor is unavailable, use the declared fallback and keep provenance honest.
