# Execution workflow

Run this sequence, collapsing trivial stages for bounded edits:

1. Classify the request.
2. Inspect an existing project.
3. Load project context.
4. Set the preservation boundary.
5. Estimate scope.
6. Select a structure preset.
7. Define information architecture.
8. Set or preserve art direction.
9. Plan intentional assets.
10. Plan product states.
11. Plan motion and reduced motion.
12. Write the implementation contract.
13. Build the signature relationship.
14. Build responsive transformations.
15. Build functional states.
16. Capture rendered evidence.
17. Critique the highest-impact gaps.
18. Repair a bounded scope.
19. Verify change, accessibility, and preservation.
20. Stop or report unresolved proof.

Parallelize only independent inspection or verification. Do not run implementation passes against the same files concurrently. Cache the project map, tokens, routes, components, assets, approved direction, and reference relationships.

For follow-ups, use the saved context and change only the new request. Do not regenerate a site or reset its direction because the user asked for one local edit.
