# Product

## Mission

Design Lagann turns design requests into scoped, responsive, functional frontend work. It supports new creation and precise evolution of existing products without erasing approved decisions or unrelated user changes.

The target is not generically beautiful UI. The target is authored, product-specific, accessible, maintainable, and proven in the rendered result.

## Operations

The request classifier selects one operation:

- create;
- redesign;
- edit;
- extend;
- repair;
- transform.

Every operation except create begins with repository inspection and a preservation boundary. Edit and repair default to minimum scope.

## Shared workflow

Design Lagann uses one host-aware sequence:

1. classify the request;
2. inspect the project and load persistent context;
3. protect approved direction and unrelated paths;
4. estimate scope and choose Fast, Balanced, or Quality;
5. set practical information architecture;
6. define or preserve the art direction;
7. plan intentional assets, complete states, responsive behavior, and motion;
8. implement the highest-impact relationship first;
9. inspect browser evidence and repair root causes;
10. detect real change, verify accessibility and scope, then stop.

Fast, Balanced, and Quality alter exploration and repair depth. They do not lower the acceptance bar.

## Host model

The Codex and Claude Code packages share the same skill and workflow engine.

Codex may use an available raster image generator for an intentional image role. Image generation is optional, not a stage gate.

Claude Code runs without an image generator. It uses local assets, qualified references, browser-composed direction prototypes, and strong typography/layout/material systems. Missing photography or illustration becomes an explicit acquisition requirement with role, crop, size, and rights notes. The design continues without fake decorative substitutes.

## Asset policy

Allowed categories are backgrounds, section backgrounds, hero/product/editorial images, transparent foreground subjects, subtle material textures, brand illustration, and imagery explicitly requested by the user.

Automatic particles, ribbons, belts, blobs, glows, noise, sparkles, floating ornaments, and decorative dividers are rejected. Empty space is a compositional decision.

## Product completeness

Applicable interfaces cover default, hover, active, focus-visible, disabled, loading, empty, populated, success, warning, error, offline, permission denied, no results, onboarding, long content, and responsive states.

Motion communicates state, hierarchy, spatial continuity, or direct manipulation. A shared token system and `prefers-reduced-motion` behavior are mandatory. Remotion appears as one optional stage only when rendered video is requested and available.

## Stop conditions

Stop when the requested outcome is proven, no meaningful source/rendered change occurs, or the bounded pass limit is reached. Never invent success when evidence is missing.
